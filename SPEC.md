# Z — AI Fashion Studio · Claude Code Build Spec

A premium 3D t-shirt studio where a user types a prompt and an AI-generated graphic appears **printed into the fabric** of a rotatable 3D tee, with the Z brand mark always on it. Lives at the `/fashion` route.

---

## 0. How to use this with Claude Code

1. This file (`SPEC.md`) and `CLAUDE.md` both live in the repo root. Claude Code reads `CLAUDE.md` automatically every session.
2. Work **phase by phase**. For each phase:
   - Start in **plan mode** — let Claude read the relevant files and write a plan. Approve it.
   - Switch to default mode and let it implement.
   - Do not move to the next phase until the phase's **Verify** gate passes.
3. Run `/clear` between phases so each phase starts with clean context.
4. **v1 = Phases 1–3 only.** Phases 4–5 (print export, payment) are listed for context but are NOT built yet.

A good opening message to Claude Code:
> Read `SPEC.md`. We're building this in phases. Start with Phase 1 only. Enter plan mode, study the referenced patterns, and write a plan before editing anything.

## 1. Goal (one sentence)

A premium 3D t-shirt studio at `/fashion` where the user describes a graphic in plain language and it appears, generated by AI, looking genuinely printed into the cotton of a rotatable 3D tee that always carries the Z brand mark.

---

## 2. The hard requirement: "printed in, not a cheap sticker"

This is the whole point of the product. The generated graphic MUST read as **printed into the fabric** — sharing the shirt's weave, matte finish, folds, and lighting. It must NOT look like a flat, glossy sticker floating on the surface.

How this is achieved (this is a material/shading problem, not an AI problem):
- The shirt uses a PBR `MeshStandardMaterial` with a **fabric `normalMap`** (the weave bumps) and a **`roughnessMap`** (matte cotton), plus ambient occlusion. Roughness stays high (~0.85–0.95) so it never looks plastic.
- The design is applied as a **`<Decal>`** (drei) that inherits that material's shading, so the print picks up the same weave and matte lighting as the shirt.
- **YOU MUST** verify this by eye against a real DTG-printed t-shirt photo and fix any "sticker" look before a phase passes.

## 3. Tech stack

- **Next.js (App Router) + TypeScript + Tailwind CSS**
- **React Three Fiber** + **@react-three/drei** (`useGLTF`, `Decal`, `Environment`, `ContactShadows`, `OrbitControls`)
- **Framer Motion** (UI micro-interactions and the reveal animation)
- **Anthropic API** for the design-director + moderation layer — model `claude-sonnet-4-6` (use `claude-haiku-4-5-20251001` if you want it cheaper/faster)
- **OpenAI `gpt-image-1`** for the graphic — generates transparent-background PNGs
- **All AI calls go through Next.js API routes** (server-side). NEVER expose API keys to the browser.
- State: React state or Zustand. **No database, no auth, no backend service in v1.**

Setup gotcha to handle: using `gpt-image-1` may require completing OpenAI's API **Organization Verification** in their console. Surface a clear error if the key isn't verified.

## 4. Architecture & contracts (build these exactly)

### 4.1 Decal zones (named placement presets)
Define a small set of named print zones, each a `{ position, rotation, scale }` preset on the tee mesh:
- `front_chest` — upper-centre front, small **(this is the default)**
- `front_full` — centre front, large
- `back_center` — centre back, large
- `left_sleeve`, `right_sleeve` — on the sleeve faces, small

These transforms are **model-specific** — calibrate them by eye for the chosen GLB in Phase 1 (drop a test PNG into each zone and confirm it sits correctly).

### 4.2 Design-director route — `POST /api/design`
Input: `{ userMessage: string, currentDesigns: Design[] }`. Calls Anthropic. Returns **strict JSON only** (no prose, no markdown fences):

```json
{
  "action": "add | replace_all | modify | remove | reject",
  "reject_reason": "string | null",
  "designs": [
    {
      "id": "stable id e.g. d1",
      "image_prompt": "detailed, on-brand prompt for the image model: a single graphic on a transparent background, premium streetwear aesthetic",
      "placement": "front_chest | front_full | back_center | left_sleeve | right_sleeve",
      "scale": "s | m | l"
    }
  ],
  "reply": "short friendly message to show the user about what changed"
}
```

System-prompt rules for this Claude call:
- Act as the **design director for Z, a premium streetwear label**. Turn the user's rough request into a strong, on-brand `image_prompt`.
- If the user doesn't say where, set `placement` to `front_chest`.
- Follow-ups like "add small flames on the sleeve" → `action: "add"` with only the new design(s); keep existing ones.
- "make the skull bigger" / "change X" → `action: "modify"` targeting the affected `id`.
- **REJECT** (`action: "reject"` with a reason) any request for hateful, sexual, violent, or illegal content, OR any third-party logo, trademark, brand name, or celebrity likeness — because these get **physically printed**. Do not silently sanitise; reject and explain in `reply`.
- Output **JSON only**.

Parse this defensively on the server (strip stray fences, validate the enum values, fall back gracefully).

### 4.3 Image route — `POST /api/generate`
Input: `{ image_prompt: string, placement: string }`. Calls `gpt-image-1`:
- `background: "transparent"`, `output_format: "png"`, `size: "1024x1024"` (use `"1024x1536"` for `front_full` / `back_center`).
- **IMPORTANT:** use `gpt-image-1`, NOT `gpt-image-2` — gpt-image-2 cannot produce transparent backgrounds (the request errors).
- **Fallback:** if transparency comes back unreliable (white fill / fuzzy edges), generate on a solid white background and strip it server-side with `rembg` (or remove.bg). Build this fallback in.
- Return the PNG (base64 data URL is fine for v1).

### 4.4 End-to-end flow
user prompt → `/api/design` (JSON) → for each returned design call `/api/generate` (PNG) → render one `<Decal>` per design at its zone, using the PNG as the decal `map` → show Claude's `reply`. Multiple designs = multiple decals.

## 5. Brand & visual rules

### 5.1 Z logo
A permanent decal, **small, on the left chest**, present on every shirt and every colourway, **not user-editable**. Keep it as one easily-moved transform so placement can change later.

### 5.2 Colourways (4, user-switchable)
| Name | Hex | Note |
|---|---|---|
| Onyx | `#141414` | soft/washed black (not pure #000 — reads more premium and renders better) |
| Charcoal | `#3A3A3C` | washed grey-black |
| Bone | `#E8E2D4` | warm off-white — the elevated neutral |
| Ice | `#F2F5F6` | cool crisp white |

Switching a colourway sets the shirt material's base colour. Keep swatches minimal and elegant.

### 5.3 Frontend aesthetic
Apply Anthropic's anti-"AI-slop" directive:

> `<frontend_aesthetics>` NEVER use generic AI-generated aesthetics like overused font families (Inter, Roboto, Arial, system fonts), clichéd colour schemes (particularly purple gradients), predictable layouts and component patterns, and cookie-cutter design that lacks context-specific character. Use unique fonts, cohesive colours and themes, and animations for effects and micro-interactions. `</frontend_aesthetics>`

Direction: dark editorial, heavy negative space, the **3D tee centre stage**, one elegant prompt bar, the 4 colourway swatches, a small "your designs" chip list (each with a remove button), soft studio lighting + a contact shadow, and a "developing onto the fabric" reveal animation while a graphic generates. It must look and work great on **mobile** (cap the renderer DPR, keep the model light, skip heavy post-processing on phones).

## 6. Phases

### Phase 1 — The premium 3D tee (no AI yet)
**Goal:** a rotatable, fabric-realistic 3D t-shirt at `/fashion`, with the permanent Z mark and the 4 colourways.
**Context (read first):** study an existing React Three Fiber t-shirt configurator to learn the `Decal` + PBR material pattern — e.g. the official drei t-shirt configurator example, and the open-source repo `paul-daniel/react-shirt-sculpt`. Reuse a **free t-shirt GLB** and state in a comment where you sourced it. (The chosen model needs front, back, and sleeve geometry for all 5 zones; if it lacks back/sleeves, note that and limit zones until a fuller model is swapped in.)
**Build:** load the GLB; `MeshStandardMaterial` with fabric `normalMap` + `roughnessMap` (+ AO), roughness ~0.9; `Environment` + `ContactShadows` + soft lighting; `OrbitControls`; the 4-swatch colourway switcher; the permanent Z decal on the left chest; define and **calibrate the 5 decal-zone transforms** by dropping a test PNG into each.
**Constraints:** simplest setup that looks premium. No AI, no payment, no backend.
**Verify (gate):** screenshot the tee in each colourway and rotated. The Z mark and a test graphic must look **matte and woven-in (not a glossy sticker)** and sit correctly in all 5 zones. Compare against a real DTG-printed tee photo and fix differences. Show the screenshots.

### Phase 2 — Prompt → AI design → live update
**Goal:** type a prompt, get a transparent-PNG graphic printed onto the tee at the parsed zone; support multiple designs via follow-ups.
**Build:** the `/api/design` route (the JSON contract in 4.2) and `/api/generate` route (`gpt-image-1` transparent, with the rembg fallback); the prompt bar; wire `designs[]` state → one `<Decal>` per design; render Claude's `reply`; the "developing" loading animation; handle `action: "reject"` with a graceful message.
**Constraints:** API keys server-side only; treat Claude's output as JSON-only and parse defensively; unspecified placement → `front_chest`.
**Verify (gate):**
- "put a skull on the back" → skull appears on the back.
- follow-up "add small flames on the left sleeve" → a second decal appears on the sleeve, the skull stays.
- a prompt with no placement → lands on the front chest.
- "put the Nike logo on it" → rejected with a clear message, nothing printed.
- every generated graphic still looks **printed-in, not stuck-on**.

### Phase 3 — Premium polish
**Goal:** make it feel like a $100 one-of-one drop.
**Build:** refine layout and typography (non-generic fonts per 5.3), Framer Motion micro-interactions, the reveal animation, the colourway UI, the designs chip list with remove buttons, a proper mobile pass (DPR cap + perf), a nice empty state with copy, and the Z wordmark.
**Verify (gate):** screenshot desktop AND mobile. It looks intentional and premium on both, orbiting stays smooth on a phone, and nothing reads like a generic AI template.
